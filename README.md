# MiniReader · 悬浮摸鱼阅读器

一个无边框、置顶的迷你 TXT 阅读器。窗口缩在屏幕角落，滚轮读下去，老板来了按一下热键整个藏起来。

**第一版**只做六件事：无边框置顶窗口 · 打开本地 TXT · 自动编码识别 · 滚轮滚动 · 老板键隐藏/显示 · 记忆窗口位置和阅读进度。

**这一版加上七件**：透明度调节 · 失焦自动变淡 · 托盘图标 · 全局快捷键可配置 · 窗口标题伪装 · 隐藏任务栏 · 边缘吸附。

---

## 1. 安装

只需要一个 Qt 绑定。**本机已经装好 PyQt5 5.15.11 / Qt 5.15.2，所以现在什么都不用装就能直接跑。**

想换成官方绑定的 PySide6：

```bat
py -3.12 -m pip install PySide6
```

或者显式安装 PyQt5：

```bat
py -3.12 -m pip install PyQt5
```

代码会自动选用已安装的那个（优先 PySide6）。`requirements.txt` 也按「二选一」写好了。

> **PyQt6 不支持。** Qt6 改了 `QTextEdit` 的换行与滚动行为，本项目的滚动像素计算没有在 PyQt6 上验证过，宁可不声称支持。

确认当前用的是哪个绑定、托盘和全局热键在**这台机器上**到底能不能用：

```bat
py -3.12 -m minireader --check
```

## 2. 运行

三种方式，随便挑一种：

```bat
:: 方式一：双击
run.bat

:: 方式二：命令行
py -3.12 -m minireader

:: 方式三：启动时直接打开某本书（TXT 或 EPUB 都行）
py -3.12 -m minireader "D:\novel\某本小说.txt"
```

也支持把 TXT / EPUB 文件**直接拖进窗口**，或者拖到 `run.bat` 上。

`run.bat` 会自动在 `py -3.12` → `py` → `python` → `python3` 里挑第一个真正能用的解释器。

## 3. 怎么用

| 操作 | 效果 |
| --- | --- |
| 滚轮 | 上下滚动，一个刻度 3 行 |
| 滚到章末再滚一下 | 进入下一章；在章首往上滚回到上一章，并落在上一章的**末尾** |
| 拖动标题栏 | 移动窗口，松手后吸附到附近边缘 |
| 拖动四条边 / 四角 | 改窗口大小（Windows 原生缩放，支持 Aero Snap） |
| `Ctrl+Shift+\`` | 老板键：整个窗口藏起来，再按一次回来 |
| `Esc` | 同上（**只在窗口有焦点时有效**，是给老板键注册失败时的兜底） |
| `Ctrl+T` 或右上角 `☰` | 开/关章节目录抽屉（目录 + 书签两个页签） |
| `Ctrl+B` 或右上角 `🔖` | 在当前阅读位置加一个书签 |
| `Ctrl+Shift+空格` 或右上角 `⏵` | 自动滚动 开始/暂停（鼠标移到正文上会临时停住） |
| `Ctrl+←` / `Ctrl+→` 或状态栏 `◀` `▶` | 上一章 / 下一章 |
| 右上角 `⚙` | 打开设置面板（排版、透明度、热键、伪装标题…） |
| 右上角 `打开` | 选一个 TXT 或 EPUB |
| 右上角 `✕` | 退出（会保存位置和进度）。勾了「关闭时最小化到托盘」则改为隐藏 |
| 托盘图标左键 / 双击 | 隐藏 / 显示 |
| 托盘图标右键 | 菜单：显示/隐藏、打开文件、不透明度档位、设置、退出 |

> **`Ctrl+空格` 是故意避开的**：中文 Windows 上它是输入法的中英文切换开关，抢过来会让用户打不了字。所以自动滚动用 `Ctrl+Shift+空格`。有测试专门盯着这一点（`test_ctrl_space_is_not_used`）。
>
> 后面 5 个是**窗口内**快捷键（`Qt.WidgetWithChildrenShortcut`），不需要注册全局热键；按下它们是「焦点在 MiniReader 里」才生效，所以设置面板开着时会被挡住，免得在热键输入框里按 `Ctrl+B` 顺手加了一个书签。

窗口默认落在**屏幕右下角**，480×360，不进任务栏、不进 Alt+Tab。

**透明度默认 100%、失焦变淡默认关闭。** 原因见下面第 8 节的 ClearType 说明——低于 100% 会让中文小字的边缘发糊，所以是「你要你才开」，不是默认糊。

## 4. 配置

配置都是纯 JSON，放在 `%APPDATA%\MiniReader\`：

| 文件 | 内容 |
| --- | --- |
| `settings.json` | 字号、字体、行高、边距、配色、滚轮行数、透明度、热键、伪装标题、吸附、自动滚动、窗口位置、上次读的书 |
| `progress.json` | 每本书读到第几章、章内偏移（按文件路径的哈希作 key） |
| `library.json` | 最近打开过的书（最多 100 本） |
| `reading.db` | **书签**（SQLite）。见下面「为什么书签是 SQLite，其余是 JSON」 |

前三个文件都是**原子写入**（先写临时文件再 `os.replace`），断电或崩溃不会留下半个坏文件；文件坏了也只是退回默认值，不会让程序起不来。**每个字段的读取都是全函数**：`{"snap_distance": "很近"}` 这种「合法 JSON、类型不对」的值会被退回默认，而不是让程序在启动时抛 `ValueError`。

`reading.db` 是**程序自己攒的、会一直长**的那类数据，所以用 SQLite；而「你要手改的偏好」留在 JSON 里。这个分界是刻意的，理由写在第 9.3 节。

新增的配置项：

```json
{
  "opacity": 100,
  "dim_on_blur": false,
  "dim_opacity": 55,
  "snap_enabled": true,
  "snap_distance": 14,
  "keep_on_screen": true,
  "disguise_title": "",
  "show_tray": true,
  "close_to_tray": false,
  "boss_key": "Ctrl+Shift+`",
  "hotkey_next": "",
  "hotkey_prev": "",
  "hotkey_opacity_up": "",
  "hotkey_opacity_down": "",

  "font_family": "",
  "font_size": 17,
  "line_height": 160,
  "margin": 16,
  "bg": "#12131a",
  "fg": "#c9cbd4",
  "autoscroll_speed": 60,
  "autoscroll_pause_on_hover": true
}
```

| 字段 | 范围 | 说明 |
| --- | --- | --- |
| `opacity` | 30–100 | 下限 30：再低就是「在但看不见」，而任务栏已经被藏了 |
| `dim_on_blur` / `dim_opacity` | 20–100 | 失焦时降到 `dim_opacity`，但**永远不会比 `opacity` 更亮** |
| `snap_enabled` / `snap_distance` | 0–60 px | 磁吸。60px 以上不像吸附，像窗口自己跳 |
| `keep_on_screen` | — | 独立开关：保证窗口永远留着能抓住的一块（见第 8 节） |
| `disguise_title` | ≤120 字 | 空=不伪装；换行/制表符会被压平 |
| `show_tray` / `close_to_tray` | — | 托盘可以随时建/删，**不需要重启** |
| `font_family` | 空=跟随系统 | 字体名。系统里没这个字体时 Qt 会自己替换，不会崩 |
| `font_size` | 10–48 pt | |
| `line_height` | 100–250 % | |
| `margin` | 0–80 px | 正文四周留白 |
| `bg` / `fg` | `#rrggbb` | 正文背景色 / 文字色。设置面板会实时算对比度，低于 4.5:1 会标黄 |
| `autoscroll_speed` | 10–400 px/s | **按像素/秒存，不按「每 N 毫秒一行」**——理由见 9.5 |
| `autoscroll_pause_on_hover` | — | 鼠标移到正文上自动暂停，移开继续 |

删掉整个 `%APPDATA%\MiniReader` 目录即可恢复出厂设置（书签也一起没了）。

**老板键的「已隐藏」状态故意不保存。** 如果保存了，下次启动就是一个看不见的窗口——而托盘可能在设置里被关掉、全局热键可能注册失败（比如被别的软件占了），两条退路同时断掉就直接锁死。所以 `settings.json` 里根本没有这个字段，这是刻意的。

**但透明度和伪装标题是保存的**，它们是「偏好」而不是「这次会话的状态」。这两类东西很容易混为一谈——早期版本连 `opacity` 这个字段名都被测试当成敏感字段禁掉了，现在测试里两半都显式断言。

## 5. 两条退路：老板键 + 托盘

全局热键用 Win32 `RegisterHotKey`（`ctypes` 直接调用），**不用** `keyboard` / `pynput` / `SetWindowsHookEx`：

- 后两者要装全局键盘钩子，容易被杀软误报，还必须常驻后台线程；
- `RegisterHotKey` 是系统提供的正规接口，退出时 `UnregisterHotKey` 干净注销。

**规则很简单：至少有一条退路，才允许隐藏。**

| 全局热键 | 托盘图标 | 能否隐藏 |
| --- | --- | --- |
| ✅ | 任意 | 可以 |
| ❌ | ✅ | 可以（点托盘图标回来） |
| ❌ | ❌ | **拒绝**，并在状态栏说明原因 |

```
全局热键不可用，已阻止隐藏（否则窗口找不回来）
```

托盘图标本身就是一条看得见、点得到的退路，所以它单独就能解锁隐藏。反过来，热键注册失败时提示会变成「可以用托盘图标恢复」。

常见失败原因是组合键被别的程序占用（`RegisterHotKey` 返回 1409）。换个组合即可，例如 `Alt+\`` 或 `Ctrl+Alt+F9`。

### 可配置的全局热键

5 个快捷键都能在设置面板里改：老板键、下一章、上一章、提高/降低不透明度。默认只有老板键绑定，其余留空。留空的项**不会**去注册。

在设置面板里点一下输入框，然后按你想用的组合即可。规则：

- **必须带修饰键**（Ctrl / Alt / Shift / Win）。裸字母会去抢所有其他程序的按键，所以被拒绝并说明原因；
- 裸的 F1–F24 例外，Windows 允许；
- `Esc` / `Backspace` / `Delete` 清空绑定（不会顺手把整个设置面板关掉）；
- **重复的组合会被当场标红并禁用「确定」**，不会等保存后静默冲突；
- 「同一组合键」判定是在**写进系统之前**做的（`register_all` 先去重再 `RegisterHotKey`），所以不会出现「注册了一半」的状态。

## 6. 编码识别

对中文小说的 txt，按下面顺序判定：

1. **BOM** —— 按 BOM 直接定（UTF-32 排在 UTF-16 前面，因为 UTF-32LE 的 BOM `FF FE 00 00` 以 UTF-16LE 的 `FF FE` 开头）
2. **严格 UTF-8 解码成功就采纳** —— 中文文本几乎不可能碰巧是合法 UTF-8
3. **按「常用字密度」给候选编码打分** —— UTF-8 / GB18030 / Big5 / UTF-16LE / UTF-16BE / UTF-32LE / UTF-32BE 一起评分，取最高分

第 3 步是重点。GB18030 极其宽松，几乎任何字节串都能解码不报错，所以「没抛异常」不算证据；而乱码里全是控制字符和生僻字，真文本里全是常用汉字——按这个打分能稳定区分。

> 顺带一个实测结论：**不要用空字节的奇偶性判断 UTF-16**。中文里 `一`(U+4E00)、`开`(U+5F00) 这类字的低位字节就是 `00`，在 UTF-16LE 里落在偶数位，和 ASCII 字符的空字节位置正好互补。实测一段正常中文，两种奇偶的 `00` 字节数都是 120，完全没有区分度。这个思路试过，是错的，所以改成了解码后打分。

判定结果和置信度会显示在状态栏；识别不准时会提示「编码可能不准」。

### 测试不会碰你的真实配置

`Settings.save()` 不带参数时写的是 `%APPDATA%\MiniReader\settings.json`——就是你在用的那个文件。测试通过 `SandboxedAppData` 把 `%APPDATA%` 指到临时目录，并且**用一条测试专门断言这个沙箱有效**（`test_the_sandbox_actually_redirects_the_default_path`），因为一旦 `data_dir()` 改成在 import 时缓存结果，所有沙箱都会静默失效。

> 这一条是踩出来的：早期版本的新测试漏了沙箱，往真实 `settings.json` 里写了 4 个我编出来的热键，程序下次启动就会真的去注册它们。现在跑完整套件前后对 `%APPDATA%\MiniReader\*.json` 做哈希比对，确认零改动。

**还有第二个更隐蔽的漏法，也修掉了。** `ProgressStore.save()` 和 `load()` 是在**调用时**才去解析 `data_dir()` 的（`Settings` 则是在 `__init__` 里就把路径存好了）。窗口里有两个防抖定时器（几何 500ms、进度 900ms），它们的槽函数在 `tearDown` 里 `close()` 之后仍可能被投递一次；而那时候 `%APPDATA%` **已经被还原成真实的了**，于是那一笔写进了读者真实的 `progress.json`。

这是真发生过的：一次 608 项的整套里，每个单独用例都有沙箱，文件却变了。修法是 `tearDown` 在还原环境变量**之前**显式 `stop()` 这两个定时器。发现它纯属因为每次都做整套前后哈希比对——单看测试输出是 608 全绿。

### 分章内核的一致性测试

分章逻辑是从「DSH 小说壁纸」插件里那份跑通的 JS 内核移植过来的（`client.js` 的 `decodeTxt` / `cleanTitle` / `marksFrom` / `splitChaptersAuto` 等）。移植最怕「看起来对」，所以这里做的是**逐字对比**：

```bat
:: 从冻结的 JS 内核导出标准答案（只在 JS 那边改动时才需要重跑）
node tools/dump_conformance.mjs

:: 然后 Python 侧断言完全相等
py -3.12 -m unittest tests.test_core
```

`tests/conformance.json` 里存着 20 个构造用例和 5 本真实小说的标准答案：每章的标题、起止偏移、卷首语标记，以及**每章正文内容的 sha256**。当前覆盖 **5,344 个真实章节**，全部与 JS 内核逐字一致。

| 书 | 编码 | 字数 | 章节数 |
| --- | --- | --- | --- |
| 同穿：我的名字响彻诸天 | UTF-8 | 1,060,749 | 482 |
| 择日走红（精校版全本+全番外） | GB18030 | 6,327,740 | 1,032 |
| 这个装备栏太棒了 | UTF-8 | 1,905,326 | 523 |
| 残血玩家 | UTF-8 (BOM) | 6,441,769 | 987 |

（章节数比「标题数」各多 1，因为每本开头都有一段正文在第一个标题之前，会作为「前言」单独成章。）

## 8. 第二批：Windows 兼容性（七项）

### 8.1 透明度调节 · 失焦自动变淡

两条路都试过，选了 Win32：

- **Qt 的 `setWindowOpacity()`** 在 Windows 上底层就是 `SetLayeredWindowAttributes`，但它**不提供**「不参与命中测试」之类的其他标志位，而且 100% 时 Qt 会把 layered 样式摘掉——正好也是我们想要的；
- **`WS_EX_LAYERED` + `LWA_ALPHA`** 直接可控，失败也有明确的返回值和 `GetLastError()`。

实现上有一个**必须知道的取舍**：

> `WS_EX_LAYERED` 的 alpha 合成是**软件合成**。低于 100% 时 Windows 会关闭该窗口的 **ClearType 次像素抗锯齿**，中文小字的笔画边缘会明显发糊。

所以默认 `opacity=100`、`dim_on_blur=false`——不是没做，是**不默认糊**。设置面板里直接写着这条取舍，让你在调的时候就知道代价。开到 100% 时 Qt 会摘掉 layered 样式，ClearType 自动回来。

**命中测试不受影响**：layered 窗口仍然正常接收鼠标事件，**没有**变成点击穿透。这是刻意的——一个点不动的窗口没法关掉自己。

动画：160ms `OutCubic`，用 `QPropertyAnimation` 驱动 `windowOpacity` 属性，所以是逐帧插值而不是一跳。

失焦变淡的触发点是 **`QEvent.ActivationChange`**，不是焦点事件：对一个已经激活的顶层窗口来说，焦点事件根本不会再来。

还有一个容易踩的坑：**打开设置面板时主窗口按定义就是「非激活」的**，这时候如果还去变淡，整个程序看起来就像坏了。所以 `refresh_opacity()` 在 `_dialog_open` 期间强制按「激活」处理。

### 8.2 托盘图标

- 图标是**代码画出来的**（`QIcon` + `QPainter`：圆角强调色方块 + 4 条深色文本线），不带任何二进制资源文件，所以 PyInstaller 打包后不会丢图；
- `QSystemTrayIcon.setContextMenu()` **不接管 Python 侧的 `QMenu` 所有权**——菜单必须挂在实例上，否则 GC 一跑菜单就空了（点了没反应的经典 bug）；
- 托盘**随时可建可删**（`sync_tray()`），不像窗口标志那样需要重启；
- 托盘提示文字跟着**伪装标题**走，否则鼠标一悬停就露馅了。

> **踩过的一个坑：`QSystemTrayIcon.isSystemTrayAvailable()` 在没有任何 `QApplication` 存活时会段错误。** PyQt5 5.15 / Qt 5.15.2 实测退出码 `-1073741819`（`0xC0000005`），**没有 Python 异常可以 catch**——`try/except` 完全拦不住。`--check` 曾经就在这个位置崩掉。现在这个方法开头有 `QApplication.instance() is None → return False` 的守卫，并且在 docstring 里标明这是承重的。

### 8.3 全局快捷键可配置

- `RegisterHotKey` + `QAbstractNativeEventFilter`，只用系统正规接口；
- `MOD_NOREPEAT = 0x4000`，按住不放不会连发；
- 退出时逐个 `UnregisterHotKey`；
- **重复注册会返回 False 且 `GetLastError() == 1409`**，所以「这组合被占了」和「这组合非法」能区分开，报错是具体的。

两个实测出来的细节：

- **同一个 `WM_HOTKEY` 会被投递两次**（两次的 `MSG.time` 不同，所以按时间去重不可行）。用 `QTimer.singleShot(0, ...)` 合并后，实测按 1 次切换 1 次、按 5 次切换 5 次。
- **`nativeEventFilter` 必须返回 `(bool, int)` 元组**，返回裸 `False` 会抛 `TypeError: invalid result from Filter.nativeEventFilter()`。

### 8.4 窗口标题伪装 · 隐藏任务栏

两者都碰窗口标志，而 Windows 上有一个硬约束：

> **运行时调用 `setWindowFlags()` 会销毁并重建原生窗口**：位置跳变、原生状态丢失，而且**已注册的全局热键会指向一个死掉的 HWND**。

所以：

- 隐藏任务栏/Alt+Tab 用 **`Qt.Tool`**，在**构造时**设定一次，之后永不改动；
- 老板键隐藏只调 `hide()` / `show()`，绝不碰标志；
- 伪装标题同时写 Qt 标题和 **`SetWindowTextW`**，并让托盘提示跟着走。**实测**：`setWindowTitle()` 本身就会同步到原生标题，无边框 `Qt.Tool` 窗口也一样（探针：改前原生标题是进程名 `python`，改后是 Qt 设的字符串）。所以 Win32 那次调用是**冗余的保险**，不是必需路径——留着是因为它顺手证明了两边一致，而不是因为 Qt 做不到；
- `apply_disguise()` 在 `__init__` 里就调用，**早于任何 `show()`**。顺手测到的一个细节：新建窗口的原生标题初始值是解释器名（`python`），如果启动时才设标题，那一刻的标题就是错的；现在窗口从没以 `python` 这个标题出现过。
- **`always_on_top` 和 `hide_from_taskbar` 改动后需要重启 MiniReader 才生效**，设置面板里对这两项直接标注「改动要重启才生效」，不假装能热切换。

`WS_EX_APPWINDOW` 的优先级高于 `WS_EX_TOOLWINDOW`——想彻底隐藏任务栏按钮，两边的位都得处理。

### 8.5 边缘吸附

纯几何，`minireader/snap.py` 不依赖 Qt，所以能脱离窗口系统单测（33 项）。

- **Qt 报的是逻辑像素，`GetMonitorInfoW` 报的是物理像素**（高 DPI 下差一个比例）。所以吸附**只用 Qt 的 `screen_rects()`**，两套坐标绝不混算；需要 Win32 的工作区时，用 `GetDpiForWindow() / 96` 把物理换算成逻辑；
- X 和 Y 轴**各自独立**判定，避免「贴上边就再也不能贴左边」；
- **只有在一次纯移动之后才吸附**。拖动缩放（或用 Aero Snap 把窗口甩到边上）时吸附会跟用户正在拖的那条边打架；
- OS 拥有拖动过程（`startSystemMove()`），所以没有 release 事件可以挂——用 **140ms 静默期定时器**判断「这一下手势结束了」；
- 拖动中途**停一下**也是静默期，所以还要检查鼠标键是否仍按着。是的话就**推迟**而不是吸附，否则窗口会在光标底下被移走，而系统还在按自己的锚点算拖动，两边会肉眼可见地打架。推迟有次数上限，避免鼠标状态卡住导致永久不吸附。

**`keep_on_screen` 是独立于吸附的开关。** 一开始把它挂在 `snap_enabled` 下面，看着很整齐，其实是错的：关掉磁吸会**静默地**一起关掉安全网。而窗口被拖到屏幕外、任务栏又被藏了的时候，连右键任务栏把它挪回来这条路都没有。所以现在吸附和「别拖丢」是两个独立承诺，前者管手感，后者管你能不能找回窗口。实现上只保证**每个轴都留着能抓住的一块**（48px 可见 / 10px 可抓），不会去扭一个用户故意摆放的跨界位置。

### 8.6 配色对比度

顺手把配色的对比度算成了代码（`ui/theme.py`，含 15 项测试），9 组文字/背景全部达到 WCAG AA：

| 用途 | 前景 / 背景 | 对比度 |
| --- | --- | --- |
| 正文 | `#c9cbd4` / `#12131a` | 11.45 |
| 状态栏、提示、对话框次要文字 | `#959aad` / `#191b24` | 6.13 |
| 警告 | `#e0b050` / `#191b24` | 8.58 |
| 标题栏、对话框正文 | `#c9cbd4` / `#191b24` | 10.61 |
| 输入框 | `#c9cbd4` / `#0e0f15` | 11.82 |
| 强调色 | `#6f9ee8` / `#191b24` | 6.32 |

原来的次要文字色 `#7b8093` 在面板底色 `#191b24` 上只有 **4.37:1，低于 AA 的 4.5 门槛**，已换成 `#959aad`。测试里保留了这条对照（`test_the_old_muted_colour_would_have_failed`），免得以后被改回去。

`relative_luminance()` 现在对非法颜色**抛 `ValueError`** 而不是返回 0.0——返回 0 会把任何拼错的颜色都算成黑色，然后给出一个看起来很合理的对比度，让整个审计变成橡皮图章。

## 9. 第三批：阅读功能（七项）

### 9.1 章节目录

目录是**和正文并排的抽屉**（`QHBoxLayout` 里的兄弟控件），不是弹出窗口。原因是这个程序的主窗口是「无边框 + 置顶 + 不进任务栏」的 `Qt.Tool`：再开一个顶层窗口，就得自己再处理一遍它的置顶、老板键、失焦变淡和任务栏标志；而抽屉天然跟着主窗口一起隐藏，**老板键按下时不会留下一块孤零零的目录**。

目录页签和书签页签合成一个 `QTabWidget`。

**165 858 章也不会卡。** 目录用 `QAbstractListModel` + `QListView`，只给可见的那十几行准备数据。实测 `set_chapters(165858)` 是毫秒级；防回归阈值定在 1.5 秒，只用来抓「不小心退化成 O(n²)」，不用来跑分。如果换成「每章建一个 `QListWidgetItem`」，同样的规模要好几秒。

当前章的高亮**不用自绘 delegate**，而是从 `data()` 里返回 `BackgroundRole` / `ForegroundRole` / `FontRole` / `DecorationRole`，配合 `QListView.NoSelection`。少一个 delegate 类，少一层绘制风险，而且**颜色是从 `theme.py` 里取的，所以对比度是被测过的**（`#12131a` 上的 `#6f9ee8` = 6.82:1，实测于真实平台）。

顶部有一个搜索框，按标题过滤；清空就恢复全文。

### 9.2 上一章 / 下一章

滚轮滚到章末再滚一下本来就能翻章（第一阶段就有），现在把它显式化成两个按钮和一个快捷键。三个入口都走 `step_chapter()` 一个函数，所以「在章首往上滚回到上一章的末尾」这个语义三处一致。

按钮在**首章禁用「上一章」、末章禁用「下一章」**，不是点了没反应。

### 9.3 书签（以及为什么它进 SQLite）

书签存的是**章内字符偏移**，不是滚动条像素。

这不是风格问题：像素偏移在你**改一次字号或者拉一下窗口**之后就指向别的地方了。真实平台实测（520×420、本章 3,759 字、锚点落在第 2983 字）：

| 字号 | 存字符 → 顶端字符 | 存像素 → 顶端字符 |
| --- | --- | --- |
| 24 | 2983（漂 0） | 1678（**漂 −1305**） |
| 12 | 2983（漂 0） | 3652（漂 +669） |
| 22 | 2983（漂 0） | 2110（**漂 −873**） |
| 30 | 2983（漂 0） | 1253（**漂 −1730**） |

存字符的漂移是 **0 字**；存像素会让读者直接跑到别的段落去。测试里两种做法**都跑一遍并互相对比**（`test_character_anchoring_beats_restoring_the_pixel_offset`），所以以后谁改回存像素会当场失败。

摘录不是另存一份文本，而是**每次从书里现算**（`Book.chapter_body(章)[偏移:]` 压平空白、截 60 字加省略号）。这样书签库不需要知道任何书的内容，也不会因为改了字体就存着一份对不上的旧文本。

**为什么书签用 SQLite，其它配置还是 JSON？** 判断标准就一条：

> **你要手改的 → JSON；程序自己攒的、会长大的 → SQLite。**

`settings.json` 是你会拿记事本打开改的东西，所以它得是能直接读的、带缩进的 JSON。书签是「点一下多一条」的数据，会自己长，键值对 JSON 迟早要整份重写。所以 `reading.db` 是一张表加一个 `(book_id, chapter, offset)` 索引。

顺带把「没有目录缓存」也说明白：目录是从 `Book.chapters` 现算的（那是加载时就切好的内存结构），再缓存一份到磁盘只会多一个会和书对不上的副本。

书签库**永不抛异常**：目录写不了就退回内存库（`persistent=False`）并在界面里说明，而不是让加书签这个动作把程序搞崩。你那份损坏的 `reading.db` 也不会被删掉——降级是「这次不用它」，不是「替你清掉」。

### 9.4 字体、字号、行距、背景色

设置面板新增一组「排版」，含字体下拉（默认「跟随系统」）、字号 10–48pt、行距 100–250%、页边距、正文背景色和文字色，外加 4 个预设（默认深色 / 护眼米黄 / 夜间纯黑 / 大字松散）。

**颜色随你调，但对比度会实时算给你看**：低于 WCAG AA 的 4.5:1 就标黄说明。深浅自定义是最容易调出「字看不见了」的地方，所以这里不拦你，但会告诉你。

改动是**即时预览**的：拖动滑块，正文当场变；点「取消」回到打开面板前的那份设置。实现上只有一个预览函数（`_preview()`），不透明度那条和排版这条共用它，避免两条路径的预览行为不一致。

**换字号不会让你跑丢。** 因为锚点是字符（见 9.3），`apply_style()` 会先记住视口顶端的字符、重排之后再滚回去。对 120MB 大文件也是同一套代码。

一个必须说清楚的精度上限：锚点记的是**行首**，所以换字号后可能往回挪**不到一行**（实测真实平台 0 字，offscreen 下 3 次换字号共漂 6–15 字）。这是「把行首对齐到顶边」这个做法的固有量化，不是误差累积——比起按像素恢复会漂上千字，不是一个量级的问题。要消掉它得让 Qt 汇报「顶边那个字的半行偏移」，它没给。

### 9.5 自动滚动

`AutoScroller` 是独立的 `QObject`（不继承控件），**时钟是可注入的**（构造函数收 `clock=`，默认 `time.monotonic`），所以测试不用 `sleep` 就能确定性地验证「1 秒走 60px」。

- 速度按 **px/s** 存，不按「每 N 毫秒滚一行」。后者在 12 号字和 30 号字下速度会差 2.5 倍——换一次字号，滚动速度就变了。px/s 是一次设定、到处一致的量。
- 位移**一律来自真实经过的时间**，不来自「第几拍」。定时器在系统忙的时候会晚到、会合并，按拍数走会越走越慢。余下的不足一像素的部分累加到下一拍，所以长时间的平均速度是准的（实测 120px/s 跑 1.2 秒走了 140px）。
- 到章末自动进下一章并继续滚；到**最后一章**就停下并在状态栏说明（`已经是最后一章`），不会卡在那里假装在滚。
- **短到不用滚的章节不会一章一章地空转下去**：`start()` 发现自己已经在底部（或者 `maximum() == 0`）时只发一次 `reachedEnd`，不进运行态。
- 鼠标移到正文上会临时暂停，移开继续（`autoscroll_pause_on_hover`，默认开）。灵感是「停下来看一眼」这个动作——自动滚动最烦的就是想看细节时它还在动。
- 信号顺序是 `stopped` **先于** `reachedEnd`，而且所有状态在发信号之前就改完。因为窗口收到 `reachedEnd` 会当场换章并重新 `start()`，状态要是没落定，新一轮会被自己刚发的信号立刻打断。

### 9.6 EPUB 支持

**只用标准库**（`zipfile` + `xml.etree`），没有加任何依赖。

支持的：EPUB 2 / 3，`container.xml` → OPF → `spine` 的顺序，`nav.xhtml` 或 `toc.ncx` 的标题都用不上也没关系（章节标题优先取 `spine` 项自己的 `toc` 映射，取不到就用正文里的标题行走同一套分章正则）。文件里嵌的 HTML 会被转成纯文本，`spine` 顺序就是阅读顺序。

**opening 判定和 TXT 一样稳**：`looks_like_epub()` 只看 ZIP 魔数和 `mimetype`，**永不抛异常**；一本 `.epub` 改名成 `.txt` 照样认得出来，反过来一本 TXT 也不会被误判。

明说不支持的：**DRM 加密的会明确拒绝**，报「这本 EPUB 有 DRM 加密，暂时打不开」，而不是解出一堆乱码。解析失败一律转成 `EpubError` / `BookError`，措辞是给人看的。有 60 个「故意弄坏的 zip」的模糊测试，确认**没漏出任何非 `EpubError` 的异常**——包括截断的、把 `mimetype` 写错的、`spine` 指向不存在的文件的、正文全是空白的。

**本机一个 EPUB 都没有**（这机器上确实不存在 `.epub` 文件），所以这 48 项测试用的是 `zipfile` **现搭的真 EPUB**（`tempfile.mkdtemp()` 里生成，跑完就删），不是桩。

### 9.7 大文件性能优化

这是这一批里改动最实在的部分。目标是**不改变任何输出**，只把「一次吃下整个文件」的写法换掉。

原来的 `bytes.decode()` 是整份解码：一次性分配结果字符串和中间缓冲。实测 120MB 的 UTF-8 文件，`data.decode()` 的峰值是 **360MB = 文件的 3.0 倍**，而结果本身只有文件的 0.7 倍。

改成 `codecs.getincrementaldecoder(编码)(errors=...)` 按 4MB 喂进去之后，峰值降到 **166MB**，而且**输出逐字节相同**——UTF-8 / GB18030 / UTF-16LE、非法字节、截断的尾字节、落单的代理对、1/3/7/64 四种分块大小，全都验过（分块大小是直接 patch `_DECODE_CHUNK` 来测的，不是造 4MB 的样例文件）。代价是每 120MB 约 0.07 秒。

分章那边原来有个慢路径的引用实现（`_score_pattern_slow`），每章每个规则都要重新扫一遍。改成对**行首做一次线性扫描**、`clean_title` 算一次共用之后：

| | 优化前 | 优化后 | 倍数 |
| --- | --- | --- | --- |
| 18.9MB 真书（残血玩家） | 0.22s / 72MB（4.0×） | **0.15s / 44MB（2.4×）** | 1.5× |
| 120MB 合成书 | 7.24s / 480MB（4.0×） | **1.33s / 286MB（2.4×）** | 5.4× |
| 分章规则打分 | 14.65s | **1.45s** | **10.1×** |
| 120MB 的 `decode` 峰值 | 360MB（3.0×） | 166MB | 2.2× |

剩下的 **2.4 倍是地板**：文件字节本身（1.0×）+ 解码出来的 `str`（0.7×）+ 分块拼接时的瞬时峰值（0.7×）。要再低只能把文件读两遍，那是拿正确性换内存，不做。

两个测量方法上的坑，记下来免得下次再踩：

- **`tracemalloc` 会让墙钟时间翻倍**，所以时间和内存必须分开测，不能在同一次运行里同时看两个数。测试里因此用的是「峰值比率」断言加一个 `old_style()` 对照（阈值 4.0×），而不是去 mock `bytes.decode`——`bytes` 是不可变类型，`mock.patch.object(bytes, "decode")` 直接 `TypeError`。
- **编码识别的对照阈值是实测出来的**：新的分块解码在 5.6MB 的 GB18030 文件上峰值是 **2.74×**，旧写法是 **6.49×**，两边都留足余量才取 **4.0×** 做门槛。

### 几个刻意为之的实现决定

- **不使用运行时 `setWindowFlags()`。** 见 8.4。
- **拖动和缩放交给操作系统。** 用 `QWindow.startSystemMove()` / `startSystemResize()`，白拿 Aero Snap 和正确的多显示器行为；只在返回 `False` 时退回手工 `move()`。实测 Qt 5.15.2 上这两个方法存在且可用。
- **窗口边框是不被任何子控件覆盖的 4px**，它既是可见的描边，也是缩放的判定区，所以不需要额外的透明覆盖层。
- **`_line_px()` 用字体度量算，不用 `blockBoundingRect(firstBlock())`。** 后者看着像「一行高」，实际是**整个段落**的高——段落会折行。实测 420px 窗口里 `lineSpacing` 是 28px、一个段落折成 3 行、`blockBoundingRect` 返回 84px（190% 行高时 134px）；再乘 3 行/刻度，一个滚轮刻度就滚 400px ≈ 14 行，滚轮变成了翻页按钮。
- **滚动用 `QTextEdit` 而不是 `QPlainTextEdit`。** 后者的滚动条是按块（block）走的，一个段落就是一格，完全没法做像素级缓动。
- **`gotoChapter` 必须先取消滚轮动画**，否则动画的下一帧会把新章节拖回旧偏移。
- **`_gesture_active` 而不是只看 `_gesture_resized`。** 构造时 `setGeometry()` 会触发一次 resize，如果那次就算「用户缩放了窗口」，**启动后的第一次拖动吸附会永远不生效**。所以只有「手势进行中发生的 resize」才记进否决位，手势结束时消费掉这个状态。
- **设置面板的高度必须自己算，不能靠 `resize()`。** 三个分组叠起来约 713px，1366×768 的办公本（减去任务栏）放不下——而这类机器正是本程序的目标。实测两个坑：① 只套一个 `QScrollArea` 会让它**在 1080p 上也照样滚动**（滚动区的 `sizeHint` 偏小，对话框就开得矮）；② 在 `__init__` 里 `resize()` **不生效**，`show()` 时布局重新激活又把它长回去（600px 屏幕上实测：720px 的对话框仍然是 720px，直接挂到屏幕外面）。真正管用的杠杆是**给滚动区设 `maximumHeight`**——那才会改变布局实际索要的尺寸——再加上对话框自身的 `maximumHeight` 兜底。按钮行放在滚动区**外面**，所以怎么缩都还点得到。
- **封装层的每个函数都不抛异常。** 它们会在窗口创建、绘制路径和原生事件过滤器里被调用；在那里抛异常不是给出好看的报错，而是直接杀掉窗口、或者从事件过滤器里穿回 Qt。
- **设置面板是 `Settings` 的唯一写入者。** 所有字段先落到一个 `dataclasses.replace()` 出来的副本上，`apply_to()` 里统一 `clamp()`，取消则丢弃。`geometry` 和 `last_book` 原封不动地跟着走——「恢复默认」是恢复**偏好**，不该把窗口挪走、也不该忘掉你正在读的书。
- **`core/` 和 `store.py` 里没有一行 Qt。** 分章、编码识别、EPUB 解析、书签库都只依赖标准库。这不只是洁癖：正因如此它们能在没有窗口系统的环境下被测，也正是因为这样，`test_store.py` 里有一条断言直接**读源码**确认没有 `PyQt5` / `PySide6` / `minireader.qt` 字样，并且确认 import 它不会把 Qt 拉进 `sys.modules`。
- **`progress.json` 存的是滚动条像素，书签存的是字符。** 两种都有各自的道理：进度是「上次就停在这个像素」，一秒内要能恢复、不必精确；书签是「我要回到这句话」，必须经得起改字号和拉窗口。9.3 那组实测数字就是这两者的差别。
- **自动滚动的定时器间隔是 40ms，但速度不按间隔算。** 40ms 只是采样频率（够顺，又不至于白烧 CPU）；真正走多少像素由 `time.monotonic()` 的差值决定。计时器晚到或合并都不会让速度变慢。
- **目录抽屉不是一个弹出窗口。** 见 9.1：主窗口是 `Qt.Tool`，第二块顶层窗口会让老板键和「隐藏到托盘」都留下漏网之鱼。
- **`QToolButton` 有 22px 的最小尺寸。** Qt 在小字号下算出来的 `sizeHint` 能低到 19px，低于可用性下限。没有取触屏推荐的 24px，是因为这套界面的目标是一个鼠标操作的、标题栏尽量薄的常驻小窗——22px 是「够点」和「不占地方」之间的取舍，测试里把这个下限钉住了。

## 11. 已知限制

- **`always_on_top` 和 `hide_from_taskbar` 改动后需要重启。** 它们决定构造时的窗口标志，而运行时改标志会毁掉已注册的全局热键（见 8.4）。设置面板里已标注。
- **透明度低于 100% 时中文小字会失去 ClearType 次像素抗锯齿**，边缘发糊。这是 Windows 软件合成的代价，不是实现 bug；所以默认 100%。
- **EPUB 不支持 DRM**，会明确拒绝并说明。也不支持 EPUB 里的图片、脚注弹窗和样式——一律转纯文本，只看字。
- **换字号后的位置精度到「行」为止。** 锚点记的是视口顶端那一行的**行首**，所以换字号后可能往回挪不到一行（真实平台实测 0 字，offscreen 下三次换字号共漂 6–15 字）。这是量化误差，不是累积误差；要消掉它需要 Qt 汇报顶边字符的半行偏移，它没有这个 API。
- **没有圆角。** 无边框窗口的圆角在 Windows 上要么靠 `DWM` 的区域裁剪（和 `WS_EX_LAYERED` 会互相干扰），要么自己画一张带 alpha 的位图；两条路都会让「4px 拖拽边框」的命中判定变复杂，收益不值这个代价。
- **全局热键只实现了 Windows。** 非 Windows 会退回「老板键不可用」，`--check` 里也会明确说明；这时若托盘可用，隐藏仍然允许（托盘是那台机器上的退路）。
- **分章靠标题正则。** 识别不出来时会把整本当一个章节，而不是硬猜一个目录出来（`shortRatio >= 0.5` 才认，宁可拒绝也不虚构）。
- **短前言不会被自动跳过。** 有的书第一章是 110 字的站点声明，打开时看着像空的——那是真的只有这么点字，翻到下一章就正常了。（`--smoke` 输出的 `滚动范围=0px` 就是这个情况，不是 bug。）
- **单文件上限 200MB。** 再大就明确报错拒绝，而不是让程序去换页换到卡死。分块解码已经把内存压到文件的 2.4 倍，但 200MB 以上一次加载的代价（几秒）已经超过「随手摸鱼看两眼」这个用途能接受的范围了。
- **目录里 16 万章时搜索框是线性过滤。** 实测够快（毫秒级），但它没有做索引；如果以后真有人拿它开两百万章的书，那里会是第一个瓶颈。
